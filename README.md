# ORCA

**简体中文** | [English](README_EN.md)

ORCA 是面向 Windows 的 PDF 翻译与阅读工具。你可以批量翻译论文或书籍，导出译文或双语对照 PDF，也可以在阅读时选中一段文字查看译文。ORCA 使用 PDFMathTranslate Next 2.9.0 和 BabelDOC 0.6.2 在本机解析和排版文档。

## 下载和打开（Windows x64）

1. 打开本仓库的 [Releases](https://github.com/ZHANGgy12138/ORCA/releases)，在 0.9.1 的 **Assets** 中下载 **`ORCA-0.9.1-windows-x64.zip`**。便携包已内置 Python。
2. 找到下载好的 ZIP 文件，**右键 → 全部解压缩**，等待解压完成。
3. 从解压后的文件夹进入 **`ORCA`**，双击 **`ORCA.exe`**。程序和旁边的 **`_internal`** 文件夹需要放在一起。首次启动时，窗口会显示资源加载进度。

如果在 ZIP 预览窗口里双击程序，Windows 可能提示 `Failed to load Python DLL`。此时请按上面的步骤完整解压，再从解压目录启动。

## 翻译第一份 PDF

1. 点击“选择文件”，一次多选 PDF；可以继续追加，重复文件自动跳过。开始前可移除文件或清空队列。
2. 选择原文、目标语言和翻译引擎。默认 Bing 免费引擎，需要联网；统一通过侧栏“引擎设置”更换。
3. 点击“每份试译 5 页”先检查效果，或选择全文 / 指定页码后翻译整个队列。指定页码应用于每一份 PDF，会提前校验；输出可选译文、双语或两种都要。
4. 文件按顺序逐份翻译。每份文档的所选 PDF 全部生成后，导出位置才会出现该文档的结果文件夹。单份失败会继续处理下一份，取消队列时保留已完成的结果。可在队列或最近任务中打开译文。
5. 右上角切换亮色 / 暗色模式，顶部标题栏融入界面。拖动顶部移动窗口，双击或使用右上角按钮最大化/还原，支持边缘调整尺寸和最小化。最近任务重开后仍保留。
6. 点击最小化左侧的悬浮窗按钮，切换为紧凑进度小窗；原翻译任务继续运行。小窗显示当前文件、已完成份数、总进度与阶段，可取消当前队列、切换置顶或返回主窗口。
7. 返回主窗口会恢复进入前的大小、位置或最大化状态。悬浮窗的位置、尺寸和置顶选择在本次打开期间保留；重启仍进入主窗口。小窗的关闭按钮会退出软件，活动任务仍会提示确认。

长文档每 50 页分段处理。扫描版、复杂公式和学术术语的效果取决于原文质量与翻译引擎，重要内容请核对原文。试译后的“翻译全文”会提交一次全文任务，已有翻译缓存可能复用；这不是断点续译。

引擎面板提供 23 个服务入口，包括 Bing、Google、OpenAI、DeepSeek、Gemini、DeepL、Ollama、Xinference、Azure、腾讯云、阿里云百炼、通义翻译、魔搭、智谱、硅基流动等。自定义 OpenAI 兼容接口可填写自己的模型名称、接口地址及高级参数。需要外部命令行程序的 ClaudeCode / CLITranslator 不包含在便携版入口中。

0.6.1 修复旧版动态引擎模块遗漏问题：构建直接扫描源码收集实际实现，并在缺少必要模块时停止。当前 23 个服务入口会按配置转换为 15 个实际适配模块，不能仅按入口名称寻找同名文件。发布自检逐一检查转换与独立子进程加载；DeepL、自定义兼容接口、智谱、魔搭和 Index 另用本机模拟服务检查请求和返回。这些检查证明组件与调用路径可用，不代表所有云端账号、模型权限或公共免费服务都已联网验证。

“测试连接”会向选中的服务发送一句简短文本，付费服务可能消耗少量额度，测试最多等待 30 秒。第三方服务是否可用取决于账号、网络和模型权限。API 密钥默认只保留在当前会话；可在引擎设置中勾选“在这台电脑上记住密钥”，点击“使用此引擎”后保存到 Windows 凭据管理器。密钥不写入普通偏好文件或历史记录。语言、主题、输出位置和非敏感模型参数会自动保存。程序不包含开发者密钥。

文档解析与排版在用户电脑运行，正文发送至所选翻译服务。模型和字体包含在便携包内；首次使用会复制到用户的应用数据目录。结果与日志默认保存在 `%LOCALAPPDATA%/ORCA`，也可以在软件内更改结果保存位置。

0.6.1 起整篇翻译缓存也使用 ORCA 应用数据目录下的 `cache/translation`，避免构建或工作进程触碰另一个安装环境的用户缓存。旧位置的缓存不会被删除或自动迁移；首次翻译可能需要重新请求原有内容。偏好、最近任务及已有 PDF 输出不受影响。

独立窗口使用 Microsoft Edge WebView2。已安装该运行时的 Windows 电脑可直接打开。本版本未做代码签名；这是供测试的 0.9.1 版本，尚未覆盖不同电脑的兼容性测试。

## 暂停续译、表格和图片

翻译中可点击“暂停并保存”。等界面提示进度已保存后再关机。下次打开 ORCA，在“可继续的翻译”列表点击“继续翻译”。任务会按原引擎、语言、页码、模型和输出设置恢复。移动过的原 PDF 可以重新定位，恢复前会核对文件内容。会话密钥可能需重新填写。取消任务和删除恢复记录会放弃相应中间进度。

每次新任务的“自动保存进度”默认关闭。开启后，已返回的译文会分批写入磁盘。意外关机时，最近一次写入之后的翻译可能需要重做。完整分段可复用，未完成分段可能重新解析、排版。只有新版创建的保存任务会出现在恢复列表。请保留应用数据目录与原 PDF。

有清晰矢量框线和可选文字的表格会按格提取文字、合并排版换行，保留段落和编号，再在格内排版。扫描表、无框表和复杂公式尚有局限。

使用 Index 时，可勾选“翻译图片中的文字”。导出时识别所选页的嵌入式位图，发送至 B站，在有可识别文字时生成附译注的 PDF，附录列出原页码、图片序号、缩略图及译文。细小装饰图会跳过，纯矢量图可在阅读界面点击“框选图片翻译”手动选区。仅框选或启用上述选项时会提交图片。

## Index-Translate 免费引擎

在侧栏“引擎设置”选择“Index-Translate · B站免费翻译”，点击“使用此引擎”即可，无需 API 密钥。使用 B站官方公开的 Index-Translate-35B-A3B 文本模型，支持阅读划词和整篇 PDF 的逐段翻译；文件在本机解析，需翻译的文字会发送至该服务。没有下载大型模型，也不需要本机显卡。

适配器采用官方请求头和翻译提示词，关闭思考模式。长段按边界分段，公式和样式标记不得拆散；空响应、被截断输出或丢失标记会报错。若全文某段接口调用失败，本次不能作为完整译文成功交付。它不能保证所有术语、语义或复杂版面都完全正确，仍需核对原文。

该接口目前免费、无需申请，属于实验性公共服务。维护者说明按 IP 限制每分钟 500 次请求、120,000 token，服务规则可能调整。ORCA 默认逐段、低并发调用，遇到限流不会绕过限制。详见官方项目 https://github.com/bilibili/Index-Translate 与维护者说明 https://github.com/bilibili/Index-Translate/issues/28 。

## 阅读翻译

侧栏选择“阅读翻译”，打开 PDF。可用滚轮连续向下阅读，页码随滚动更新；上一页、下一页和页码输入也可用于快速定位。支持缩放和适合宽度，页面保留原始颜色。通常只渲染当前位置附近最多 5 页，活动选区所在页面额外保留，适合长文档。选中文字后，右侧自动显示所选服务返回的译文，可复制，也可关闭自动翻译后手动提交。翻译栏可收起或调整宽度，滚动、翻页与缩放保留已显示的译文。

语言与服务沿用现有设置。每次只发送选中文字，最长 6,000 个字符，超过时提示缩小选区，不会截断后悄悄提交。连续划选时取消旧请求，只显示最新选区结果；单次请求最多等待 30 秒。阅读翻译独立于整篇翻译队列，不生成新的 PDF。

打开文档时预热翻译工作进程（只初始化本机依赖，不发送文字或健康检查）。同一引擎配置下复用工作进程和连接；最近最多 64 项成功译文仅缓存在内存中，同一文本、语言和引擎配置再次划选时无需联网。更换/关闭文档或退出程序会清空这份缓存；取消正在进行的网络请求会结束对应进程，下次请求可能需要重新初始化。

Bing 免费入口使用 Bing 翻译网页会话：首次访问网页获取临时会话参数，再向网页使用的翻译接口提交文字，读取返回译文。不需要用户 API 密钥；文档仍在本机阅读，但选中文字会发送至 Bing。读取时短期复用同一会话参数（ORCA 自定 120 秒期限，并非微软保证的有效期），减少重复访问网页；遇到正常认证/参数失效可刷新一次，限流会直接提示稍后重试。首次初始化、网络、服务限流和长文本分段仍会产生等待，不能保证即时返回，也不能仅凭接口推断微软使用的具体模型。整篇翻译仍使用原有上游处理流程。

PDF 阅读组件随软件提供，阅读文件无需联网；翻译是否需要联网取决于所选服务。扫描页缺少文字层时，可选择 Index 并框选区域识别和翻译；加密 PDF 需先解密。复杂双栏、公式和文字编码可能影响选区提取，请核对右侧原文。当前仅显示当前选区，不保存划词历史或批注。

## 升级

当前没有自动检测、下载或安装更新。升级时先结束任务并退出 ORCA，将新版便携 ZIP 完整解压到一个新文件夹，再运行新版的 `ORCA.exe`。不要只复制 EXE，也不要在运行中覆盖旧版文件。

偏好设置、最近任务和默认输出独立保存在 `%LOCALAPPDATA%/ORCA`，0.9.1 继续读取原来的数据；自选输出目录也不会随程序更换。未选择记住的 API 密钥仍需在新会话重新填写；已保存的密钥在同一台电脑、同一 Windows 用户下自动读取。确认新版正常后可自行清理旧的程序目录，保留文档和应用数据目录。

新版本和更新说明可在本仓库的 [Releases](https://github.com/ZHANGgy12138/ORCA/releases) 中查看。

## 从源码构建

在 Windows x64 的 Python 3.12 虚拟环境中，从仓库根目录运行以下 PowerShell 命令。将 `PATH_TO_PUBLIC_BABELDOC_ASSETS` 替换为包含 `fonts`、`models`、`cmap` 和 `tiktoken` 四个子目录的路径。已解压的 0.9.1 便携包内也有这份资源，位于 `ORCA\_internal\resources\babeldoc`。

```powershell
python -m pip install -r requirements-build.txt
$env:PYTHONPATH = "$PWD/vendor"
python scripts/prepare.py --assets PATH_TO_PUBLIC_BABELDOC_ASSETS
python scripts/vendor_pdfjs.py
python -m PyInstaller --noconfirm desktop.spec
python scripts/package.py
```

`vendor` 包含本次构建使用的引擎源码，构建前请把该目录加入 `PYTHONPATH`。源代码开发启动也使用同一目录：`$env:PYTHONPATH = "$PWD/vendor"; python app.py`。

发布前运行 `ORCA.exe --engine-test`：逐一检查 23 个配置入口转换后的 15 个模块，在新子进程中加载依赖，并使用本机模拟服务检查五类连接/阅读请求。此项不需要云端密钥、不访问外网，报告写入测试应用数据目录。构建时的 `build/bundled-module-manifest.json` 用于确认必要源码模块均已收集。

`ORCA.exe --free-engine-test` 另行向 Bing、Google、硅基公共免费服务和 Index-Translate发送一次简短连接测试，每项最多等待 30 秒。这是联网测试，其结果可能因网络或服务限流变化。两项测试均建议设置独立 `PDFMT_DATA_DIR` 和 `PDFMT_REPORT`，不与日常数据混用。

测试入口：设置 `PDFMT_DATA_DIR` 为隔离测试目录，执行 `ORCA.exe --diagnostics`；若设置 `PDFMT_TEST_INPUT` 后执行 `--self-test`，会使用免费 Bing 引擎试译该 PDF 的第 1 页，生成可检查的诊断报告。该测试会向 Bing 发送所选页面正文。`--reader-test` 会打开该 PDF、选取第一页的一小段文字并调用 Bing，检查阅读界面、主题、翻页及悬浮窗返回。
